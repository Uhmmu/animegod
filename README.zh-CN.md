把 AnimeGod 指向你已经有的那些文件夹就行。它会按字幕组的命名习惯读懂文件名，
去 Bangumi 和 AniList 找到这部番，用 libmpv 播放，叠上弹幕，并记住你看过什么——
全部在你自己的 Mac 上完成。不上传、不改名、不移动。

## 开始使用

1. **[下载最新的 DMG](https://github.com/Uhmmu/animegod/releases/latest)**，把 AnimeGod 拖进「应用程序」。
2. 打开它，点 **添加媒体库文件夹**，选中动画所在的位置——外置硬盘也可以。
3. 等扫描跑完，点一下 **查找元数据**，就可以开始看了。

> 应用为 ad-hoc 签名，未经过公证。首次打开时 macOS 可能需要你右键点击应用
> 并选择 **打开**。

**当前版本：0.3.2** —— 整季下载现在就是「一部番」该有的样子：一个文件夹、主页上
一张带真实封面的卡片，而且在第一集下完之前就已经匹配好番剧了。下载完的资源会
持续做种，不再莫名其妙退回队列；被你在访达里挪走文件的任务会暂停，而不是从头
再下一遍。

## 媒体库

你的文件保持原样，AnimeGod 只读不写。

- **从不重命名、移动或修改文件**，重新扫描也一样。
- **读得懂字幕组的文件名**：`[Group] Title [01][1080p]`、`Title.S02E04`、
  `第三季 第16集`、小数集（`13.5`）、版本号（`07v2`）。
- **支持多个媒体库根目录**，包括外置硬盘，改名或重新挂载后依然有效。
- **蓝光 `.iso` 镜像与普通剧集一样被扫描收录。**

<details>
<summary>更多细节</summary>

- 使用安全作用域书签，卷宗改名或重新挂载后媒体库依然可用。
- NCOP/NCED/PV/Menu/MV/SP 会被分类，而不是混进正片列表；标题里的盗版站广告标签
  （`【更多蓝光电影访问 www.…】`）和技术尾缀（`2006 RERiP 1080p DTS-WiKi`）会被
  去掉。
- 成人影片编号（`SONE-615` 这类）不会进入媒体库。
- 一个文件夹里包含两部作品时会拆成独立条目（前篇/後篇总集篇电影、合集电影）；
  特典文件夹（`SPs`、`特典`）作为特别篇归属于对应作品。
- 同一部电影的不同编码版本（例如 DoVi 与 SDR）合并为一集，播放器内可切换版本，
  默认 SDR。
- 在磁盘上重命名文件夹后重新扫描，身份迁移会让元数据、个人记录和观看历史继续
  跟着文件走。

</details>

## 元数据

- **Bangumi**（海报、简介、评分、制作公司、吐槽箱、话题与日志）和
  **AniList**（元数据、MAL 交叉 ID、评论、制作公司）。
- **查找元数据** 会为所有未关联的作品匹配最可能的结果，把明显可疑的放进
  **审核匹配**，由你快速过一遍。
- **数据源故障不会影响本地媒体库**——每份关联和数据都独立存在 SQLite 里。

<details>
<summary>更多细节</summary>

- 自动猜测的关联会显示置信度，可用 **更改匹配** 修正。
- 社区条目（吐槽箱、话题、日志、评论）可打开原始来源页面。
- Bangumi 使用 v0 API，AniList 使用 GraphQL。

</details>

## 播放器

内嵌 libmpv（MPVKit）的原生窗口，播放界面始终保持深色。

- **认真做的 HDR**：基于信号的 HDR10/HLG/杜比视界检测，在支持的显示器上输出
  BT.2020 EDR，自动色调映射，还有诊断面板（**⌘⇧D**）。
- **蓝光镜像** 直接打开正片，章节和拖动定位都可用，全程不挂载任何卷宗。
- **带章节分段的时间轴**，悬停气泡显示时间和章节名，可平滑拖动定位。
- **选集面板** 就在标题旁边，按 正片 / SP / 音乐与片头片尾 / 预告 / 特典 分栏。

<details>
<summary>格式、控制与快捷键</summary>

- H.264/HEVC/AV1、10-bit、VideoToolbox 硬件解码、多音轨/字幕轨、外挂字幕自动
  发现（`sub-auto=fuzzy` + `subs`／`字幕` 文件夹）、手动加载外部字幕。
- 上下渐变遮罩上的扁平图标按钮；倍速、音轨、弹幕、字幕、版本以气泡面板的形式
  从按钮弹出。
- 章节菜单、播放速度 0.5×–3×、音量（点击静音，滚轮或 `↑/↓` 调节）、字幕/音频
  延迟。
- 键盘：`Space`、`F`、`N`/`P`、`D`、`M`、`↑/↓`，以及 `←/→`——短按跳 10 秒，
  长按 2 倍速，短按后长按 3 倍速；每个操作都有屏幕提示，双击全屏。
- 符合条件的杜比视界 Profile 8.4 MP4/MOV 使用 Apple 原生播放路径；MKV 和
  Profile 7 使用 HDR10 基础层。DVD 镜像会被识别并明确提示，而不是播放失败。

</details>

## 弹幕

弹幕由 Core Animation 原生绘制在画面上，并与播放器自己的时钟同步——暂停立即
定格，拖动进度和改变倍速也不会和画面脱节。渲染器从不影响 HDR 管线。

- **两个源可合并**：弹弹play、Bilibili，或者两个一起，重复的弹幕只显示一条。
- **弹弹play** 按文件哈希识别剧集，不用把发布文件名复制进搜索框。
- **Bilibili 无需账号**；可选的 `SESSDATA` Cookie 只是扩大你自己账号的可见范围。
- **弹幕管理面板**（`M`）：最近 30 秒的弹幕或全集搜索；点击跳转到对应时间，
  右键屏蔽该文字或发送者。

<details>
<summary>筛选、控制与缓存</summary>

- 针对密集番剧：10 秒内的重复弹幕合并为一条并显示 ×N，密度滑杆均匀减少其余
  弹幕（多次重复的始终保留），可隐藏过长弹幕，屏蔽词支持普通文本或
  `/正则表达式/`。
- 播放栏控制全部自动保存：开关（`D`）、不透明度、字体大小、行距、显示区域和
  最大行数、滚动速度、同屏最大数量、按类型和彩色弹幕筛选、±10 秒偏移、刷新和
  重新匹配剧集。
- 同一行的弹幕之间保持间距，放不下的会被丢弃而不是重叠。
- 弹幕按数据源和剧集缓存在本地，可离线重播；只有 **刷新弹幕** 会重新拉取。
- 弹弹play 需要在 [dev.dandanplay.com](https://dev.dandanplay.com) 免费申请
  AppId/AppSecret，并在 **设置** 中填写。
- Bilibili 没有文件识别接口，因此按标题和集数匹配，再从官方 protobuf 分段接口
  按该集自己的 `cid` 拉取——多 P 投稿也会取到对应分 P 的弹幕池。遇到区域限制
  会如实提示，不影响播放。

</details>

## 在线字幕

视频里没有你偏好语言（默认简体/繁体中文）的字幕时，AnimeGod 会判断出番剧、季、
集数和发布版本，并行搜索四个字幕站，并且**只在足够有把握时**自动加载最佳结果；
否则用一个小提示让你自己挑。

- **射手网(伪) assrt.net**、**SubDL**、**OpenSubtitles**、**Jimaku**（仅日文），
  各自的密钥在设置中填写。任何一个出错都不影响其他源。
- **BD 字幕绝不会自动加载到 WEB 视频上**，反之亦然。
- 季度合集和 ZIP 会解包出对应集；GBK/Big5 转换为 UTF-8；ASS 由 libass 渲染，
  并使用字幕包自带的字体。

<details>
<summary>更多细节</summary>

- 字幕菜单分为 **内嵌**、**外挂文件** 和 **在线** 三组；**搜索字幕…** 可按语言、
  格式、来源、字幕组、匹配度、版本和文件名挑选。
- 下载的字幕按集缓存，重播时无需再次搜索。
- 匹配优先看是否同一集、发布版本是否兼容，然后才按你的语言和格式顺序
  （ASS/SSA 优先于 SRT）。
- 文件名表明中文字幕已内嵌的版本（`[CHT]`、`[简日内嵌]`）默认跳过，可在设置中
  更改。
- 密钥保存在 AnimeGod 的本地设置文件里，不用钥匙串。

</details>

## 查找资源

同时搜索十个动漫种子站——动漫花园、蜜柑计划、萌番组、Anime Garden、ACG.RIP、
末日动漫、Nyaa、AnimeTosho、SubsPlease、TokyoTosho——并把不同站点上的同一个种子
合并为一条。只提供动漫站点；成人、游戏和漫画条目在解析时就被剔除。

- **从动画页面搜索**会把这部作品的所有名称一起发出去（Bangumi 中文名和原名、
  AniList 罗马音、文件夹标题）。能补上缺集的资源会标记为 **New**。
- **「剧集合辑」是「不想下合集」的答案。** 同一批结果换一种排布：每个字幕组的
  一整季合成一行，除集数外的一切都要对得上——字幕组、季、分辨率、编码、片源、
  字幕语言——所以 1080p 简日 不会和 720p 繁日 混在一堆。点一下开始整季。
- **缺的集从隔壁字幕组补**：某组没发的那一集从条件最接近的另一条发布线取，
  标记为借用，绝不用生肉补有字幕的一季。没有任何一条线覆盖全季时，会额外给
  一行跨字幕组合成的完整季。
- **结果陆续显示**，慢的或被拦截的站点不会拖住其他站点。

<details>
<summary>筛选、诊断与细节</summary>

- 每个标题都会解析出字幕组、集数或合集范围、分辨率、编码、片源和字幕语言/形式
  （简/繁/日，内嵌/内封/外挂）。可按类型、分辨率、字幕和字幕组筛选；按最佳匹配、
  最新、做种数或体积排序；默认隐藏不相关的条目。
- 每一季都会显示覆盖了多少集、总体积和最弱的做种数——有一集没人做种就会拖住
  整季。媒体库已有的集会跳过，没人发过的集数会直接列出；如果一「季」基本都是
  别人的文件，就不会被当作一季提供。
- 续作单独计算：标了 S2、从第 1 集重新编号的一季，按它自己的编号衡量，而不是
  和同一次搜索里仍在数 29–38 的字幕组混为一谈。
- **Source Details** 显示每个站点的状态和耗时，**Retry Failed** 只重试失败项。
- 每条资源都可以：用种子客户端打开、复制磁力链接、保存 `.torrent`（按 info hash
  校验）或打开原始页面。会记住最近的搜索。

</details>

## 下载

**内置 BitTorrent 引擎**（静态链接 libtorrent），下载资源无需另装客户端。

- **可以直接下到媒体库目录里**，下载完成后作为普通剧集被扫描进来，不用搬运。
- **整季落在同一个文件夹里**，以番剧命名，而不是并排摊开十二个文件夹。
- **整季在媒体库里是一张卡片**，带真实封面和一个总进度环；剧集还在下的时候，
  点这张卡就能进番剧页面。
- **下完之前就匹配好**：下载一部库里没有的番时会问你它是哪部——整季只问一次，
  下载结束后不用再手动匹配。
- **整季是排队下载，不是一拥而上**：同时下 4 个（目录菜单里可改 1–8），其余按
  集数顺序等待。
- **边下边播**：开头 32 MiB 落盘后就能播，点播放按钮用 AnimeGod 自己的播放器
  打开，剩下的继续下。
- **下载完成自动解压**：`.rar`／`.zip`／`.7z` 的资源会变成能直接播放的剧集，
  而不是打不开的压缩包。

<details>
<summary>更多细节</summary>

- 退出后任务保留进度，重启继续；可暂停、继续、移除（可选是否删除文件）、重新向
  Tracker 汇报。
- 每个任务都有自己的文件夹，单文件种子也不例外，下载目录不会散落一堆 `.mkv`。
  一集一集下回来的，之后也可以在下载列表里右键合并到同一个文件夹——文件由引擎
  搬运，做种不中断，腾空的文件夹会被自动清掉。
- **下载完成的资源会持续做种。** 做种名额不再和下载数挂钩——它只占上行，而且
  下载永远优先分到名额。
- **文件被挪走的任务会暂停，不会重新下载。** 在访达里挪动下好的剧集是很平常的
  操作，为此重下一遍 600 MB 不是合理的反应。
- 目录菜单同时列出媒体库目录和最近用过的目录，任务开始后也能换目录而不中断。
  若开始下载时目录不可用（硬盘拔出、目录被删），会自动改用下一个可用目录并
  提示。
- **连通性可见**，因为它决定 BT 速度上限：DHT 节点数、UPnP/NAT-PMP 是否成功
  映射端口，映射失败时会说明手动转发能带来什么。
- 保存在媒体库之外的任务会提供「把下载目录加入媒体库」。
- 还没进库就播放的文件不会记录观看进度、自动缓存或弹幕匹配——这些等它进库
  后才有。
- 引擎调优：多个 DHT 引导节点、本地节点发现、PEX、向所有 Tracker 汇报、允许但
  不强制加密、同时监听 IPv4 与 IPv6，并为每个任务注入公共 Tracker。

</details>

## 订阅

追一部番，新一集自己下回来。最快的创建方式是在「查找资源」里筛好之后点铃铛。

- **订阅只追之后发布的**——季中订阅不会把已播的整季一次性拖回来；回补旧集要
  单独打开开关。
- **每集只下一个**，已在媒体库或之前下过的不再下；没人做种的会输给有节点的。
- **所有动作都记录在「Recent Activity」里**。自动下载只有在看得见、关得掉的
  时候才让人放心。

<details>
<summary>更多细节</summary>

- 一条规则由字幕组、分辨率、字幕语言、必含/排除关键词和起始集数组成。
- 没有集号的资源只有在规则指定了字幕组或关键词时才会自动下载，避免误下整季合集。
- 支持合作发布：规则写 `LoliHouse` 能匹配 `[喵萌奶茶屋&LoliHouse]`，这才是字幕组
  实际的发布方式。
- 启用的规则每 30 分钟检查一次。

</details>

## 剧集缓存

为放在外置硬盘上的动画准备的。

- **自动缓存**：剧集首次播放时在后台复制到本机，复制期间播放继续从硬盘读取。
- **看完即释放**：播放到 ≥90% 后关闭会自动删除这份自动缓存——它是首次播放到
  看完之间的缓冲，不是永久副本。
- **离线播放**：拔掉硬盘后索引仍在——已缓存的正常播放，其余显示 请插入硬盘。

<details>
<summary>更多细节</summary>

- 每集都有手动复制按钮（带进度和取消），动画页面还有 **全部缓存**；手动缓存
  从不自动删除。对正在自动缓存的剧集发起手动缓存会直接接管这份副本。
- 播放时优先使用已完成的缓存，所以追番途中拔掉硬盘也不会打断当前这一集。
- **缓存管理器**（来源 → 剧集缓存）：总占用、按动画分组并显示观看标记、实时
  进度、取消、在访达中显示、单集删除、全部清除，以及两条自动规则的开关。
- 副本存放在 `Application Support/AnimeGod/Episode Cache`，启动时和每次重新
  扫描后都与数据库核对，清理孤立文件和崩溃残留。

</details>

## Bangumi 排行榜

Bangumi 发布的所有全站排名：五个频道（动画、书籍、音乐、游戏、三次元）以及
网站提供的所有筛选项（分类/来源/题材/地区/受众/平台/分级…），每个频道一个菜单。

## 个人记录

- **观看记录来自真实播放**（不足 15 秒的会被忽略）；播放到 90% 即标记为已看，
  并自动更新追番状态。
- 每部作品的 **状态、评分、笔记、评论、标签、收藏、重看次数**——**排名与评分
  严格分开**，可在「我的排名」中调整顺序。
- **追番日记** 根据观看历史自动生成。
- **统计** 把一年变成一份报告：总观看时长、观看次数、看完的集数、按月/星期/
  小时的习惯、看得最多的动画和制作公司、你评分最高的作品——全部本地计算。

## 翻译

内置 DeepL 兼容的翻译服务（批量请求、自动识别免费/专业版端点、结果缓存到本地），
用于外语评论——**原文与译文并排显示**，原文从不被替换。

## 外观与语言

跟随系统 / 浅色 / 深色，播放器窗口始终深色。界面支持 **English、简体中文、
日本語**（设置 → 语言，重启后生效）。

## 开发

环境要求：macOS 14+、Xcode 26+、XcodeGen。

```sh
swift test
xcodegen generate
xcodebuild -project AnimeGod.xcodeproj -scheme AnimeGod -configuration Release build
```

- **`AnimeGodCore`**（SPM 包）包含模型、GRDB 数据库、扫描器/解析器、元数据源、
  翻译和统计——均可独立测试。
- **应用目标** 使用 SwiftUI + AppKit，播放基于 LGPL 版本的 MPVKit。分发二进制
  文件前请阅读 `THIRD_PARTY_NOTICES.md`。
- 界面文字保存在 String Catalog 中。命令行构建后运行
  `scripts/sync-localizations.sh DerivedData/<task>` 同步新文字，
  `scripts/check-localizations.py` 列出未翻译的条目。
- 可选的在线数据源测试：
  `ANIMEGOD_LIVE_TESTS=1 swift test --filter 'Bangumi.*ProviderTests'`。
- 构建产物上的无界面冒烟测试：`-smokePlayerTest`（自动播放第一集、切换全屏、
  输出布局尺寸）、`-smokeEpisodeSets "<标题>"`（用真实站点数据拼出整季）、
  `-smokeAppearanceSnapshots`。加上 `-AppleLanguages "(ja)"` 可切换语言运行。

## 数据与隐私

所有数据都在你的 Mac 上——媒体库、元数据缓存、观看历史、个人记录、统计、翻译、
弹幕匹配、弹幕缓存和剧集缓存索引都保存在本地 SQLite 数据库中
（`~/Library/Containers/com.uhmmu.AnimeGod/Data/…`），缓存的剧集文件在同一容器
里。**不会上传任何数据。**

只有你主动要求时才会联网：你调用的元数据源、Bangumi 排行榜、你配置的翻译服务、
你开启的弹幕源、你配置的字幕站（会发送标题、ID、集数和文件名，OpenSubtitles
另有一个由文件 128 KiB 计算的哈希）、你搜索的资源站，以及你开始的下载所连接的
BT 网络。BT 是点对点协议，和任何种子客户端一样，与你交换数据的节点能看到你的
IP 地址。
